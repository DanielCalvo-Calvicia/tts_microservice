## Goal

Install the service from a **clean clone** of the pushed branch, fetch the voice, and run the suite, to prove that what is in git is enough (F1, F11).

## Read first

[../../../deployment/deployment.md](../../../deployment/deployment.md) ("By hand"), facts F2, F3 and F7 of the [tasks README](../../README.md).

## Files

None changed. The clone lives outside the workspace (the scratchpad or a temporary folder), never inside `tts_microservice`.

## Steps

1. Confirm the commit is on the remote: `git -C tts_microservice status -sb` shows no "ahead". The clone has what is pushed, not the uncommitted documents.
2. Clone into a new empty folder, next to a copy of `shared-logging` (it has no repository, F3), so that `-e ../shared-logging` resolves:
   ```powershell
   git clone --branch feature_ai_claude_2 https://github.com/DanielCalvo-Calvicia/tts_microservice.git <temp>\tts_microservice
   Copy-Item -Recurse D:\Hobbys\IA\OBLIVION\shared-logging <temp>\shared-logging
   ```
   Do not copy a `.env`, a `windows` venv or `models/`.
3. In the clone: `python -m venv windows`, then `windows\Scripts\python.exe -m pip install -r requirements.windows.txt`.
4. `windows\Scripts\python.exe scripts\fetch_voice.py` (about 60 MB; it needs network). Ask the maintainer before the first download, and name the file, the source (the Piper voices host used by `piper.download_voices`) and the size.
5. `windows\Scripts\python.exe -m pytest`.
6. Delete the temporary folder.

## Acceptance criteria

- The install finishes without compiling anything and without a warning about a missing package.
- `fetch_voice.py` ends with `Piper voice en_GB-alan-medium is ready` and exit code 0; a second run says it is already ready and downloads nothing.
- The suite passes with the same count as the working folder (136 on 2026-11-05) or with a difference explained in *Notes*.

Clone of `origin/feature_ai_claude_2` (HEAD `54a6259`, in sync with the working folder's branch) into a temporary folder in the session scratchpad, outside the workspace; `shared-logging` copied beside it without caches or venvs; no `.env`, no `windows`, no `models/`. ### Findings and deviations

1. **The working folder and the pushed branch differ in `contracts`.** The working folder has uncommitted edits to `requirements.windows.txt` and `requirements.linux.txt` that point to `contracts_microservice-0.16.0` (the 0.16.0 wheel is untracked, the 0.15.0 one is deleted in the working tree). The clone tested 0.15.0, which is what is pushed. The edit is not part of this plan and was not touched; `CLAUDE.md` and the docs still say 0.15.0 and need the maintainer's decision on when 0.16.0 is committed (T-04).
2. **`httpx` is needed by the tests.** The one warning shows `fastapi.testclient` uses `httpx`, and the suite passes with it installed. T-01.3 step 1 already says it goes to `requirements-dev.txt`, not away; the audit's and F2's "nothing imports it" is true of the service code only.
3. **Versions drift from what T-01.3 step 3 quotes.** A clean install today resolves fastapi 0.162.0, numpy 2.5.4 and onnxruntime 1.31.1; T-01.3 and F4 quote fastapi 0.139.0, numpy 2.5.3 and onnxruntime 1.30.0 (the working venv). Both pass 136 tests, so nothing was pinned; T-01.3 should record the versions it tests.
4. The pip log in the clone carries no warning about a missing package, but pip printed its usual "new release of pip" notice (irrelevant).
5. Not covered here, as the task says: the voice file in a Docker image, other Pythons (3.11, 3.12) and arm64.
