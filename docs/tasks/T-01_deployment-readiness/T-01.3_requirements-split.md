## Goal

The deployed install contains only what the service runs on. Today `pytest`, `ruff`, `black` and `mypy` are in both requirements files, `httpx` is listed but never imported, and nothing is pinned (debt D-5, F2).

## Read first

`requirements.windows.txt`, `requirements.linux.txt`, `pyproject.toml`, `deployment/config/catalogue.toml` (how `requirements` is chosen per OS, and the `[services.stepper]` example of a service with a third key), `deployment/CLAUDE.md`, [../../deployment/deployment.md](../../deployment/deployment.md).

## Files

| Action | Path |
|---|---|
| Modify | `requirements.windows.txt`, `requirements.linux.txt` (runtime only) |
| Create | `requirements-dev.txt` (pytest, ruff, black, mypy, and `httpx` if the test client needs it; nothing else) |
| Modify | `docs/deployment/deployment.md` ("By hand"), the Development part of `README.md`, `CLAUDE.md` (Commands) |
| Modify | `deployment/docs/DEPLOYMENT.md` if it names the files (T-02.4) |

## Specification

1. First confirm that `httpx` is unused: search the service source (not `windows/`, not `testclear/`) and the tests. If a test needs it, it goes to `requirements-dev.txt`, not the runtime file. If `fastapi.testclient` needs `httpx` (it does for the Starlette client), it is a **dev** dependency.
2. Runtime files keep: fastapi, uvicorn, python-dotenv, pydantic, pyttsx3, numpy, `piper-tts>=1.8.0,<2`, `-e ../shared-logging`, the vendored `contracts` wheel. Do not touch the last two lines (the tool and `contracts/scripts/bundle.py` depend on them).
3. Add upper bounds only where a tested version exists (the venv has fastapi 0.139.0, numpy 2.5.3, onnxruntime 1.30.0 on Python 3.14); do not pin what was not tested. Record the tested versions in *Notes*.
4. The deployment tool installs `requirements.<os>.txt` only, so a fresh deploy no longer installs the dev tools; developers run `pip install -r requirements-dev.txt` too.
5. Do not change `catalogue.toml` (the file names stay).

## Acceptance criteria

- A clean venv with only the runtime file starts the service (`main.py` answers `/health`) and a clean venv with both files passes the whole suite.
- `pip list` of the runtime venv shows no pytest, ruff, black or mypy.
- Documents name the right file for tests.

## Verification

Create two throw-away venvs outside the workspace; run `main.py` in the first and `pytest` in the second; delete both. Record the commands and counts in *Notes*.
