## Specification

- `is_available` stays `true` on a fallback (ADR-006). `reason` is `None` when the configured engine is the one speaking, and a short constant-prefix text when it is a fallback, with the configured engine, the engine in use and the cause (the `SynthesisFailed` message that `new_speech_synthesis` already logs as `reason`).
- The cause text must not contain a secret, a full home path or a stack trace: the message of `SynthesisFailed` names the voice and the model folder only (check this in the test).
- The dependency direction does not change: the port lives in `application`, the adapters implement it, the composition root wires it. `tests/architecture/test_dependency_rules.py` stays green.
- Keep the existing log line `Piper unavailable; falling back to pyttsx3` unchanged: deployment documents and T-01.2.4 name it.

## Acceptance criteria

- With a missing voice, a corrupt voice and a missing espeak, `/available` answers `is_available: true` and a `reason` that names the fallback; with a loadable voice `reason` is empty.
- Brain's preflight (read in T-01.2.1) is unaffected; no field was added to `contracts`.
- Documents listed under *Files* are updated and say what was built.

## Verification

`windows\Scripts\python.exe -m pytest` from the service folder; the three fallback cases above are tests. Count the new total and write it in the documents that name the count.

**Conflict to settle when this task starts (found in T-01.1.4).** The cause text that `new_speech_synthesis` logs today is `Piper voice 'en_XX-nothing-medium' is not in <absolute models folder> (fetch it with: python scripts/fetch_voice.py from the service folder, or deploy again)`. The absolute folder is a full path with the user's home directory (on the drill machine `C:\Users\<name>\AppData\...`). The specification above says the `reason` must not contain a full home path. So the reason cannot just copy the logged text: build it from the voice name and the **folder name** (`models`) or a relative form, keep the log line as it is, and test both. Not changed in the log line, because T-01.2.4 and the documents name it.
