## Goal

The log line `... falling back to pyttsx3` is the evidence the documents, the failure drill and the Docker checks rely on (F6). Make a test fail if it stops being written.

## Read first

`tests/composition_root/test_engine_selection.py`, `tests/composition_root/test_tracing.py` (uses `shared_logging.testing.capture`), [../../../operations/monitoring.md](../../../operations/monitoring.md).

## Files

| Action | Path |
|---|---|

## Specification

Wrap the three existing fallback tests (missing voice, corrupt voice, missing espeak) in `with capture("tts") as logs:` and assert one record at level `error` whose message is exactly `Piper unavailable; falling back to pyttsx3` (or `espeak unavailable; falling back to pyttsx3`) and which carries a non-empty `reason` field. Add the opposite case: the loadable-voice test emits no `falling back` record and one `Piper voice loaded` record (if the fake engine path logs it; otherwise assert only the absence).

Do not change the log messages. If a record shape differs from the assumption (key names), read `shared_logging.testing` and use its real shape.

## Acceptance criteria

The three fallback tests assert the error record and its `reason`; the happy-path test asserts there is no fallback record; all pass, and each fails when the corresponding `logger.error` line in `tts_dependencies.py` is deleted (check once by hand).

## Verification

`windows\Scripts\python.exe -m pytest tests\composition_root\test_engine_selection.py`, then the whole suite; record the total.

## Notes

Tests may assume the message strings are constants (service rule: constant strings with keyword fields).

### Result (2026-11-06)

**Built.** Only `tests/composition_root/test_engine_selection.py` changed (no new test functions, so the total stays **157**). Record shape (read in `shared_logging.testing`): `capture("tts")` yields a `MemorySink` whose `records` are dicts with `message`, `level` (`"ERROR"`), `logger` (`composition_root.dependencies.tts_dependencies`) and the keyword fields as top-level keys (`reason`). Two helpers: `_fallback_records(logs)` (every record whose message contains `falling back`) and `_the_one_fallback_record(logs, message)` (exactly one record, with that exact constant message, level `ERROR`, the logger above, and a non-empty `reason` string).

| Test | Log assertion |
|---|---|
| Piper voice loads (fake engine) | no fallback record |
| Missing voice | one `Piper unavailable; falling back to pyttsx3`, `reason` names the voice and "is not in" and keeps the full folder path (the log keeps what `/available` hides) |
| Corrupt voice | one `Piper unavailable; falling back to pyttsx3`, `reason` starts with `Piper could not load` |
| Missing espeak | one `espeak unavailable; falling back to pyttsx3`, `reason` contains "is not installed" |
| pyttsx3 chosen explicitly | no fallback record (a choice is not a fallback) |
| espeak loads (fake engine) | no fallback record |
| Real Alan voice (skipped when the file is absent) | exactly one `Piper voice loaded` record with `voice == en_GB-alan-medium`, and no fallback record: the lines the Docker and deploy checks grep for |

**Deviation from the specification.** The specification says to assert `Piper voice loaded` only "if the fake engine path logs it"; it does not (the fake replaces `PiperEngine.load`), so that line is asserted in the existing real-voice test instead. That test is skipped on a machine without the voice file, so there the happy-path line is not pinned; the absence of a fallback record is pinned in every case.

**Acceptance "fails when the logger.error line is deleted", proven by mutation** (scratch script in the session scratchpad, not in the repository; original bytes restored in `finally`, hashes checked, `git status` shows only the earlier T-01.2.2 edits). Nine mutations, all caught: Piper `logger.error` deleted; espeak `logger.error` deleted; Piper message reworded; espeak message reworded; Piper line demoted to `warning`; Piper `reason` field dropped; espeak `reason` field renamed; `Piper voice loaded` reworded in `piper_engine.py`; a fallback line added for an explicitly chosen pyttsx3. The log messages themselves were not changed.

**Verification.** `windows\Scripts\python.exe -m pytest tests\composition_root\test_engine_selection.py`: `9 passed`; whole suite `157 passed, 1 warning`. File kept LF (as before). **Documents:** `docs/operations/monitoring.md` now names the test that pins the lines.
