## Goal

`scripts/fetch_voice.py` is the only step between a deploy and the Piper voice, and **no test touches it** (F7). Pin each of its outcomes, so the deployment tool and the Docker build can rely on its exit code.

## Read first

`scripts/fetch_voice.py`, ADR-006, F7 of the [tasks README](../../README.md).

## Files

| Action | Path |

| Modify | `scripts/fetch_voice.py` only if a test shows a defect (state it in *Notes*) |
| Docs | the exit-code table in `docs/deployment/deployment.md` ("The Piper voice") if the behaviour differs from it |

## Specification

The script is not a package: load it with `importlib.util.spec_from_file_location` from the repository root, and replace `voice_is_usable`, `fetch` and (for the atomic-move case) `piper.download_voices.download_voice` with fakes. No network, no real model, no `.env` read.

Cases, each a test:

1. `TTS_ENGINE=espeak` or `pyttsx3` and no `--voice`: exit 0, "no Piper voice needed", `voice_is_usable` and `fetch` not called.
2. Engine piper and the voice already usable: exit 0, `fetch` not called.
3. `--voice other` with `TTS_ENGINE=espeak`: the voice is checked and fetched anyway.
4. Engine piper, voice missing, `fetch` succeeds: exit 0.
5. `fetch` raises (no network, unknown name, full disk): exit 1, the message and the "will start with the pyttsx3 voice" hint go to stderr.
6. Atomic move: a fake download that writes the files while `voice_is_usable` says the downloaded voice does not load: `RuntimeError`, and **neither** `<voice>.onnx` **nor** `<voice>.onnx.json` is left in the model folder; the temp folder is gone.
7. `.onnx` present but `.onnx.json` missing counts as "not there".

## Acceptance criteria

All seven cases pass and fail if the corresponding line of the script is changed. Exit codes stay 0 (ready or not needed) and 1 (could not fetch). No new exit code is introduced.

## Verification

`windows\Scripts\python.exe -m pytest tests\scripts` then the whole suite; record the new total.

## Notes

### Result (2026-11-06)

**Built.** `tests/scripts/__init__.py` (empty) and `tests/scripts/test_fetch_voice.py`: 16 tests (the seven cases of the specification, some parametrized, plus extras). The script is loaded from its file with `importlib.util.spec_from_file_location`; `load_dotenv` is replaced in the loaded module, so **the real `.env` is never read**; the environment (`TTS_ENGINE`, `TTS_PIPER_VOICE`, `TTS_PIPER_MODEL_DIR`) is set per test with `monkeypatch` and the model folder is in `tmp_path`; `voice_is_usable` and `fetch` are fakes for the `main()` cases, `piper.download_voices.download_voice` and `piper.PiperVoice` are fakes for the others. No network, no real model.

| Case | Tests |
|---|---|
| 1 other engine, exit 0, nothing called | `espeak` and `pyttsx3` (parametrized) |
| 2 usable voice, exit 0, no fetch | explicit `piper`, and the default engine (piper) |
| 3 `--voice` with `TTS_ENGINE=espeak`: checked and fetched | 1 |
| 4 missing voice, `fetch` succeeds, exit 0, nothing on stderr | 1 |
| 5 `fetch` raises (`OSError` no network, `ValueError` unknown voice, `OSError` disk full): exit 1, message and hint on stderr, no success line, hint not on stdout | 3 |
| 6 atomic move: a download that does not load leaves the model folder empty and the temp folder gone; a download that raises half way leaves nothing; a good download is moved model first and config last, the temp folder is inside the model folder (`.fetch-*`) and gone afterwards | 3 |
| 7 `.onnx` without `.onnx.json` is "not there" (the voice is not even loaded); the reverse too; both files that load are usable; both that do not load are not | 4 |

**Defects in the script.** None found; `scripts/fetch_voice.py` is unchanged (`git status` confirms). **Documents:** the exit-code sentence of `docs/deployment/deployment.md` already matched the behaviour; it now also names the stderr texts, `--voice`, and the test file.

**Acceptance "fail if the corresponding line is changed", proven by mutation.** A scratch script (session scratchpad, not in the repository) changed one line of `fetch_voice.py` at a time, ran `tests/scripts`, and restored the original bytes (hash checked after each run and at the end). Eleven mutations: other engine exits 1; usable voice exits 1; `--voice` ignored for other engines; failure exits 2; failure exits 0; hint printed on stdout; config moved before the model; no check that the download loads; model without config counted as there; failure message dropped; scratch folder outside the model folder. The first run caught ten; the eleventh (scratch folder outside the model folder, which would make the final move non-atomic across filesystems) survived, so one assertion was added to the good-download test; the second run caught **all eleven**. Exit codes stay 0 and 1; no new code.

**Verification.** `windows\Scripts\python.exe -m pytest tests\scripts`: `16 passed` (none skipped: piper is installed in this venv; the tests that import piper use `importorskip`, so on a machine without it they skip rather than fail). Whole suite: **`157 passed, 1 warning`** (141 + 16). Documents that name the count updated: `README.md`, `CLAUDE.md`, `docs/architecture/architecture.md`, `docs/requirements/requirements.md` (and FR-10).

**Unblocks** T-02.1 (strict Docker build): it can rely on exit code 1 meaning "could not fetch".

The deployment audit listed "exit code 1 covers every failure" as a problem. On reading the code again, the existing two codes are enough for a strict Docker build: engines other than Piper already exit 0, so "fail on non-zero" cannot break them. What was missing is the **policy** (which services must fail the build), and that is T-02.1.
