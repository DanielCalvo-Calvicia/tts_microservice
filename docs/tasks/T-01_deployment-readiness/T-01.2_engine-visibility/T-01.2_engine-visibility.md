## Goal

Make the engine that is really speaking visible to a tool, and pin with tests the behaviours the deployment depends on: the fallback happens, it is logged, and the voice fetch fails in a defined way.

## Exit criteria

A test fails if the service falls back and does not say so; a deployment tool can read from the running service whether it is on the fallback; `fetch_voice.py` has tests for each of its outcomes.

**Met on 2026-11-06:** the fallback log lines are pinned (T-01.2.4), `/available` carries the `reason` (T-01.2.2, ADR-008), `fetch_voice.py` has 16 tests (T-01.2.3); the suite gives 157 passed. The tool reading `reason` is T-02.2.
