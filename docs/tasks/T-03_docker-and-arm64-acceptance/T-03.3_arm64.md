## Goal

Find out whether tts works on a Raspberry Pi 4 or newer: that `piper-tts` and onnxruntime install on aarch64, that the voice loads, and that a sentence is rendered faster than it takes to say it (debt D-4, NFR-7, NFR-10). Nothing about arm64 has been run.

## Read first

The preconditions of [T-03](T-03_docker-and-arm64-acceptance.md), `deployment/docs/DEPLOYMENT.md` (the Raspberry Pi parts and "Voice files"), `deployment/docs/USER_GUIDE.md` (the Pi steps).

## Files

None changed.

## Steps

Two paths; do the native one first, because the tool and the Pi's normal use are native:

1. **Native on the Pi:** `python3 oblivion.py doctor --host pi`, `validate`, `deploy --host pi --system-deps` (ask first), `status --host pi --remote`. Look at the `pip install` of tts: `piper-tts` and `onnxruntime` must install from wheels (no compiler).
2. On the Pi, read the log: `Piper voice loaded`, no fallback line.
3. **Speed:** call `POST /process/batch?text=<a sentence of about 10 words>&sample_rate=24000` three times from another machine, record the times, and compare each with the length of the returned audio (`bytes / (2 * 24000)` seconds).
4. **Docker on the Pi** (optional, only if the maintainer wants it): the same as T-03.1 and T-03.2 with the Pi's Docker context named in each command.

## Acceptance criteria

- Piper installs and loads on aarch64, or the exact failure is recorded.
- The time of a sentence is below its audio duration (NFR-10), or the measured factor is recorded.
- Memory and CPU while rendering are noted (`top` during a call).

## Verification

Install lines, log lines and the three timings, in *Notes*.

## Notes

If Piper does not run on the Pi, the supported configuration for that machine is `TTS_ENGINE=espeak` (no download, ADR-005); say so in the documents instead of leaving the default broken.
